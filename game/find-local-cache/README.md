# Пригодность объекта на время одного Find

Частный прототип 1.3.72, продолжение профиля кадра от 9 ноября 2026.
Ничего не устанавливать в обычную игру и не публиковать автоматически.
Модели, LOD, частота анимаций, lock менеджера ресурсов и симуляция не меняются.

## Алгоритм build-r3

Искомый объект неизменен на протяжении одного штатного Find. На проверенном
пути положительные условия shader(3)/unique texture(5) с обоими заполненными
ключами всегда отвергают его в strict-режиме без записей. При этом non-strict
пригодность зависит только от того же объекта и формы списка. Поддерживаются
пара 3/5 или та же пара после одного skin-условия 1/2 с обычной/обратной
полярностью. Дополнительный хвост сохраняется и обрабатывается полностью.

`local_find.h` запоминает non-strict результат каждого native kind 1..28
отдельно для двух полярностей. Четыре 32-битные маски на стеке содержат
валидность и результат; повторное условие не вызывает native dispatcher.
Все условия обходятся в прежнем порядке. Поле cached key самого условия не
влияет на non-strict результат у native kind 1..28. Код линейно
пропускает **только** группы с занятым положительным префиксом 3/5.
Нет отдельного индекса, построения таблиц, удержания NI-ссылок или кэша между
кадрами. Последняя группа всегда передаётся исходному Find: он должен иметь
возможность создать следующую группу. Нулевой ключ, другая форма,
другой поток, неизвестный kind/полярность, цепочка длиннее 32 условий или
предел 16384 пропусков возвращают управление исходному поиску с текущей
группы. Если non-strict условие ложно, поиск возвращает NULL, как исходный
Find, без перехода к следующим группам. Все записи/выделения остаются штатными.

Горячий цикл не вызывает VirtualQuery. В нём заимствуются только текущие живые
указатели, которые принадлежат этому же штатному вызову. Только VIEW может
использовать быстрый путь; при возврате из вызова ничего не сохраняется.

`plugin.c` — отдельный pinned-модуль с guard частного каталога/marker. При
режиме 0 entry Find вообще не меняется. В режиме 1 меняется только его entry
RVA 18E3C8, исходные пять инструкций исполняются в RX-шлюзе. Перед установкой
проверяются полные тела Find, AND, predicate dispatcher, обоих геттеров, RTTI
и поиска свойства, с корректировкой только настоящих PE HIGHLOW relocation.
Нет лабораторной сети, возврата в матч, создания/удаления моделей и индексов.

## Проверки

* 1000 наборов / 4000 поисков с фактическими инструкциями Find/AND/dispatcher,
  конструктором группы, клонированием/связыванием/сбросом условий. Сравниваются
  указатель выбранной группы, все байты heap, порядок/размеры выделений,
  callee-saved регистры и ret4. Аллокатор, листовой конструктор handle и
  читающие геттеры контролируемо подменены. Это не запуск полной игры.
* Отдельный поиск в цепи 16390 занятых групп проверяет предел 16384 и передачу
  остатка нативному коду с теми же тремя выделениями.
* 3000 проверок actual native shader/texture getter, RTTI/property traversal,
  non-strict read-only и занятого strict-отказа. Подменены только листовые
  виртуальные запросы type ID. Все байты NI-данных неизменны.
* 45 проверок с тремя базами игры и порчей каждого из семи защищённых тел.

`test_native.py` явно сбрасывает Unicorn translation cache после смены entry
и требует реального покрытия пропусков. Ранняя версия без этого выполняла
закэшированный исходный блок; нулевое покрытие было обнаружено проверкой.
Невозможные конечные отрицательные unique-условия исключены из генератора:
сам исходный Find бесконечно создаёт для них новые группы. Это не краш игры.

Ранний build-r2 поддерживал только список без хвоста. Оба настоящих матча
native-abba-1/cache-abba-1 завершились без ошибок, но у прототипа eligible=0
и skipped=0: дополнительные условия мира отправляли его в fallback.
Coverage-gate остановил ту серию. Это не успешная оптимизация; исходные
сборки и результаты сохранены. Новый build-r3/setup-r2 проверяет полный хвост.

## Сборка и запуск

Из checkout, Python `C:/Users/Paw/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe`:

```powershell
python game/find-local-cache/build.py --out C:/PawsFindQA-20261109/build-NEW
python game/find-local-cache/prepare.py --out C:/PawsFindQA-20261109/setup-NEW --build C:/PawsFindQA-20261109/build-NEW
python game/find-local-cache/run.py --setup C:/PawsFindQA-20261109/setup-NEW --out C:/PawsFindQA-20261109/native-NEW --mode 0
python game/find-local-cache/run.py --setup C:/PawsFindQA-20261109/setup-NEW --out C:/PawsFindQA-20261109/cache-NEW --mode 1
```

Каждое имя должно быть новым. Runner отказывается начинать измерение, пока
открыта любая другая k2.exe. Для сравнения нужны последовательные A/B/B/A,
одинаковые observer/D3D DLL, копия Случайно2, камера 2,0, 2560×1440, три обхода
и минута симуляции. Метрики пропусков не доказывают ускорение; нужны p99,
длинные кадры и совпадающие CRC. Не трогать тестовые копии соседних чатов.

`prepare_manual.py` готовит отдельную копию с native по умолчанию и двумя
командами для ручного сравнения, без observer/автоматического матча. Это
отдельный шаг после игровых проверок; одно наличие скрипта не означает их
успешного выполнения. Локализация продукта и выпуск в этот этап не входят.
