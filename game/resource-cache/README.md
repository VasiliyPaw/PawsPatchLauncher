# Кэш и предварительная подготовка ресурсов — локальная тестовая сборка

Kohan II 1.3.72 / Arcane Wars. Встроено во все восемь вариантов вспомогательного
EXE, без новой галочки. Опубликованная бета и установленная игра не меняются.
Возврат в идущий матч и старое автоматическое восстановление через лобби выключены.

## Что исправлено

В оригинальной `KKC_ResourceCacheManager::SetWeights` (RVA `1B5C02`) цикл
пересчёта размеров использует веса изменяемого класса для всех остальных классов.
После обработки класса с нулевым весом VRAM у моделей, анимаций и текстур
оказывается нулевой лимит VRAM. Это воспроизведено исполнением исходных инструкций
и подтверждено живыми таблицами кэшей. Ресурсы повторно загружались при возвращении
камеры на прежний участок даже на паузе.

`cache.c:rc_weights` сохраняет штатные общие бюджеты и индивидуальные веса,
распределяет размеры по весу каждого класса, обрабатывает создание нового класса
и нулевую сумму весов. Выгрузка, вытеснение LRU и восстановление графических
ресурсов остаются штатными. Безразмерного удержания объектов нет.

## Подготовка до показа

`rc_tick` вызывается после штатного кадра приложения, на VIEW-потоке. При загрузке
мира и на паузе он делает два конечных прохода по метаданным ресурсов, сначала
по войскам, затем по остальным эффектам. Готовятся ранее запрошенные модели NIF
и анимации KF из `Units`, `Spells`, `Effects`, `Projectiles`, `GlobalPowers`;
портреты, интерфейс и декорации не перебираются. В незапаузенном бою принудительный
прогрев не выполняется.

Поиск и асинхронный Request защищены штатной блокировкой менеджера. Ожидание
завершения загрузки, подготовка графического объекта и Release выполняются после
освобождения этой блокировки. Ссылка существует только в пределах одного вызова;
между кадрами не сохраняются указатели на ресурс/граф. Рекурсивный вход подавлен.
На выходе из мира и при переходе загрузка → игра курсор прохода сбрасывается.

Мягкий бюджет — 40 мс на экране загрузки и 2 мс на паузе. Одна штатная операция
непрерываема и может превысить бюджет: в проверенном сохранении максимальная
заняла 500 мс. Именно поэтому прогрев не выполняется в незапаузенном бою.
Он пропускается при свободных RAM/виртуальных адресах менее 384 МиБ,
загрузке памяти от 90%, отключённом штатном ResourceCaching и заполнении кэша
соответствующего класса от 75%. Незавершённые и используемые ресурсы пропускаются.

`RendererMultithreaded`, игровые правила, RNG, команды, сохранения и сетевой
протокол не изменяются. Новых пунктов интерфейса и строк для перевода нет.

## Проверки и воспроизведение

`build_native.py --out <новая папка>` собирает импортонезависимый x86-код и
`ResourceCachePayload.cs`. Требуются уже используемые в проекте TinyCC win32,
Python, pefile, Keystone, Capstone и сохранённый runtime 1.3.72; пути и хеши
зафиксированы в скрипте. Данные и код выделяются отдельно, адреса ASLR пересчитываются.

`test_native.py --native <папка>` исполняет оригинальную функцию и новый код в
Unicorn: исходный дефект, бюджеты, три расположения ASLR, регистры, новые классы,
нулевые веса, ограничения прогрева, парные Request/Release и порядок блокировок.

`build_helpers.py --baseline <build-report.json беты 4> --native <папка> --out <новая папка>`
собирает восемь локальных EXE версии `0.5.0-cache-test.1`. Все старые входы
проверяются по SHA-256, встроенные native-ресурсы сохраняются без изменений.
`test_transactions.py --report <новый build-report.json>` проверяет установку,
частичные записи, откат, отказ на изменённых инструкциях и сохранение выделенного
кода при неопределённом результате отката. Реальная установка производится
только на остановленных потоках нового, проверенного процесса.

`prepare_qa.py` копирует существующий стенд в отдельную папку и добавляет только
наблюдатель времени/кэшей. Возврат в матч не подключается. `scenario.py` использует
штатные сетевые команды, частные профили и копию сохранения. Для продукта
устанавливается `PAWS_RESOURCE_CACHE_PRODUCT=1`, чтобы наблюдатель измерял уже
установленный рабочий код. Версия и хеши частной квитанции должны соответствовать
тестовой сборке. Масштаб камеры 2,0 нормализуется одинаково для A/B, включая
штатное обновление матриц камеры; отбор армии использует компонент организации
`4E1AE0` с обратной ссылкой на её актор. Поля компонента не принимаются за GTID.

`analyze.py --run <старая сборка> --run <новая сборка> --out <отчёт.json>` сравнивает
кадры и загрузки, проверяет масштаб и совпадение штатных контрольных сумм у
участников на одинаковых тактах симуляции. Это локальные сетевые проверки;
они не доказывают одинаковую скорость на другом ПК/видеодрайвере.

## Основные восстановленные адреса (RVA)

| RVA | Назначение |
| --- | --- |
| `13C634` | кадр приложения, точка вызова подготовки |
| `1B5C02` | распределение размеров по весам |
| `1B546D`, `1B61C8` | штатный пересчёт UVars, изменение размера кэша |
| `1C99F4`, `1C9AEA` | Request / Release ресурса |
| `18AC10` | подготовка NiAVObject, только VIEW-поток |
| `4D34A4`, `4D3510` | таблицы NiAVObjResource / NiSeqResource |
| `5F3FD4`, `5F3F98` | менеджер ресурсов / рендерер |

Подробные результаты и ограничения итогового A/B находятся в отдельном отчёте
`docs/verification-resource-cache-20261107.md`. Полного устранения всех рывков
или повышения постоянного FPS этот модуль сам по себе не доказывает.

## Продолжение: остаточные рывки

`prepare_profile.py`, `stage_probe.h`, `analyze_stages.py` — частный наблюдатель
для дальнейшего исследования; в принятые helper не входит. Он проверяет нативные
точки вызовов, измеряет вложенные стадии кадра, KF/texture loads и создание
экземпляров. `PAWS_CACHE_RAM_PERCENT` / `PAWS_CACHE_KF_WEIGHT` — только временные
диагностические изменения в памяти принадлежащих QA процессов. Обычный кэш и
ручной Start-Test их не устанавливают.

Большой кэш уменьшил повторные KF-загрузки примерно с 500 до 29, но сохранил
кадры 127–143 мс. Найден следующий горячий путь: `WorldView → 2D25CB`, обработка
видимой области и видовых объектов. Подробности и границы доказанного:
`docs/investigation-render-hitches-20261107.md`. Принятый `cache.c` не менялся;
полное устранение рывков не реализовано.
