# Временный кэш условий графической группы — 9 ноября 2026

**Результат: в этой серии уменьшилось время регистрации групп и длительность
повторных пиков кадра. Полного устранения рывков и общего прироста FPS не
установлено. Сборка оставлена отдельной тестовой копией, без выпуска.**

## Что изменено

В пределах одного Find запоминается read-only non-strict результат каждого
native kind 1..28 отдельно для двух полярностей. Четыре stack bitset занимают
16 байтов. Все условия, включая дополнительные хвосты, обходятся в штатном
порядке. Пропускаются только группы с заполненной положительной парой 3/5,
которые гарантированно провалят strict без изменения ключей. Последняя группа
обрабатывается оригиналом: он должен сохранить возможность создания новой.

Порядок поиска, выделения, клонирование/сброс условий и записи ключей остаются
нативными. Неизвестный тип/полярность, >32 условий, нулевые ключи, другая форма
префикса, другой поток и предел 16384 пропусков включают исходный путь.
Если non-strict false, результат NULL совпадает с исходным Find. Кэш живёт
только в текущем стеке; моделей/NI-ссылок/индекса/межкадрового хранения нет.

Модуль меняет только entry 18E3C8, проверяя семь полных native диапазонов с
настоящими HIGHLOW relocation. В режиме 0 entry вообще не трогается.
Установщик требует private root/marker, VIEW и совпадающий код; модуль pinned.
Горячий цикл не вызывает VirtualQuery. Модели/LOD/частота анимаций, симуляция,
lock менеджера ресурсов, установленная игра и оригинальные сейвы не менялись.

## Серия A/B/B/A

Один замороженный build-r3 и setup-r2 во всех четырёх случаях. Идентичные SHA
observer, D3D DLL и нового модуля проверены. Два настоящих процесса на одном
ПК/GPU, Случайно2 (1280), камера 2,0, окна 2560×1440, лимит 30 fps. Три обхода
между областями армии, затем >60 секунд симуляции. Sampler адресов кода и все
старые графические опыты выключены; D3D setter/state-block исходные (-1).
Игровые проверки согласованы с соседним чатом и выполнялись последовательно.

## Корректность

4001 сравнение compiled prototype с фактическими
инструкциями Find/AND/dispatcher/constructor/clone/reset: совпали выбранный
указатель, весь heap, аллокации, nonvolatile регистры и ret4. Контролируемые
stubs: аллокатор, handle leaf ctor и read-only getters/RTTI. Есть отдельная
цепь 16390 групп: ровно 16384 пропуска и те же три
нативных выделения после fallback. Это эмуляция пути, не полной игры.

3000 проверки реальных shader/texture getter, RTTI/property traversal
и полного хвоста с контролируемыми type-query leaves подтверждают read-only
свойство: heap прежний. 45 проверки трёх баз и порчи каждого
из семи диапазонов подтверждают работу ASLR/byte guard.

В четырёх полных матчах 70/74/70/69 общих тактов четырёх контрольных значений,
расхождений и игровых ошибок нет. Оба участника каждого матча продвинули
симуляцию минимум на минуту; все восемь процессов завершились exit 0.
Guard не зарегистрировал skipped/unchecked indexed draws.

Осмотрена пара настоящих снимков исходного варианта и прототипа с армией:
модели/местность/интерфейс отображаются, явных пропавших моделей не видно.
Снимки не идентичны: момент паузы, позиции/анимации и ресурсы слегка различаются.
Это дополнительное ограничение точности, не полная визуальная приёмка эффектов.
Один ПК, два процесса на одном GPU; кэши ОС/драйвера не очищались. Другой ПК,
Интернет, смешанные версии и многочасовой матч в этом этапе не проверены.
