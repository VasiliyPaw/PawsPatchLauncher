# Release notes

User-facing release notes contain only changes relevant to players, in concise
language. Apply this to launcher history, signed catalog changelogs and GitHub
release descriptions, in every translation.

Do not include test results, pending validation, implementation details, specific
debugging incidents, changes that were subsequently reverted, reminders for all
players to update, or disclaimers about already desynchronized matches.

Keep technical evidence and acceptance limits in separate verification documents.
Describe the final behavior directly; avoid repeating features that did not change.
