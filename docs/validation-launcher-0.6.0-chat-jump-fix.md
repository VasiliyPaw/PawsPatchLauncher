## Исправление

- По уточнению пользователя положение кнопки **не изменено**: нижний отступ 20. Порог появления увеличен с 80 до **200 логических пикселей от конца**. При просмотре более старого окна кэшированной истории кнопка также доступна: новые сообщения могут находиться за пределами текущих 200 строк.
- Нажатие не пересоздаёт сообщения и изображения, если уже показано последнее окно истории.
- При изменении высоты содержимого во время анимации (например, после загрузки изображения) прокрутка корректирует конечную точку и доходит до нового конца. Ручное управление по-прежнему прерывает анимацию.
- Возврат не требует сетевого запроса. Порог автоматической подгрузки предыдущей страницы не менялся.

## Подключение ресурсов и статуса — ещё не завершено

В этой итерации серверные настройки, миграции и обработчики не изменялись. Уже подключённые серверные измерения базы/файлов и проверка сессии/очистки сохранены. Статистика трафика, обработчиков и писем, а также проверка почты/Storage API **не стали подключёнными** от пересборки клиента.

Проверены доступные инструменты и официальные источники. У текущего подключения нет операции получения полной биллинговой статистики и отдельного настроенного доступа Resend. Имена переменных окружения Supabase/Resend отсутствуют; содержимое хранилищ учётных данных, SMTP-пароль и браузерные токены не извлекались.

- [Supabase Management API](https://supabase.com/docs/reference/api/introduction): доступ требует отдельного PAT/OAuth. [Scoped PAT](https://supabase.com/docs/guides/platform/personal-access-tokens) предпочтительнее полного доступа; доступность ограниченных токенов необходимо проверить на аккаунте. Счётчики запросов API не эквивалентны оплачиваемому трафику или всем вызовам Edge Functions.
- В публичной схеме Management API не найден подтверждённый маршрут полного биллингового usage. В исходниках Dashboard используется отдельный platform endpoint; его поддержка для серверного токена не подтверждена. Браузерную сессию для обхода этого ограничения не использовать.
- [Resend Usage API](https://resend.com/docs/api-reference/usage/retrieve-usage) предоставляет дневной/месячный расход и лимиты, но на момент проверки обозначен private beta. Необходимо проверить доступность для аккаунта. [Обычные quota-заголовки](https://resend.com/docs/api-reference/rate-limit) — возможный поддерживаемый источник расхода, но не основание придумывать тариф/лимит.

Следующий этап требует отдельных согласованных серверных доступов провайдеров с минимальными правами. Ключи не должны попадать в лаунчер, репозиторий, журнал или сообщение чата. Нельзя обещать заполнение всех показателей только после создания ключа: доступность каждого источника ещё предстоит проверить. Неизвестные значения сохраняются неизвестными, а не подменяются нулями или зелёным статусом.
