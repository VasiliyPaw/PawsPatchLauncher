# Подключение мониторинга — Paw’s Patch Launcher 0.6.0

Дата: 2026-09-08. Серверные изменения применены по явному разрешению пользователя; подготовлен новый тестовый кандидат. Публичные release/feed/tag не менялись. Предыдущие кандидаты, левое меню, логотип и исправление возврата вниз чата сохранены.

## Подключено

- Resend: подтверждение домена и разрешения отправки, агрегаты отправленных/доставленных/ошибок/возвратов за текущий день и месяц. Чтение содержимого писем и отправка тестовых писем не используются.
- Supabase: health Auth, DB, REST, Storage; список активных обработчиков; число запросов и ошибок обработчиков за последние 24 часа. Сумма включает все пять развёрнутых функций, в том числе мониторинг.
- Приватный бакет сейвов: доступность API, приватность, максимальный файл 20 MiB. Это проверка чтения параметров, не сквозной тест загрузки/скачивания пользовательского сейва.
- Существующие фактические размеры базы/файлов, проверка активного лаунчера и очистки удалённых аккаунтов сохранены.
- Независимый серверный цикл каждые 15 минут. Кнопка «Обновить» в лаунчере читает последний сохранённый результат, не вызывает провайдеров заново. Состояние старше 30 минут при отображении помечается устаревшим; ошибка следующего опроса не превращает прежнее число в ноль.
- В статусе есть срок замены Supabase PAT, предупреждение за семь дней и красная отметка после истечения. Текущий ключ следует заменить **до 8 октября 2026**, дата задана консервативно на 00:00 UTC, поскольку кабинет показал только день истечения.

## Что нельзя выдавать за подключённый биллинг

| Показатель | Реальная доступность |
| --- | --- |
| Исходящий и кэшированный трафик | Dashboard usage вернул 401 даже с разрешённым полным экспериментальным PAT. В проверенных публичных схемах нет заменяющего биллингового endpoint. Плашка «В кабинете» и переход в официальный Supabase; не ноль и не фиктивная заполненность. |
| Вызовы обработчиков | Реальный аналитический счётчик **за 24 часа**, не месячное оплачиваемое потребление. Месячный лимит к нему не применяется. |
| Письма | Реальные агрегаты **отправки**, не входящей почты. Resend Usage API недоступен этому аккаунту (404), quota-заголовков на проверенных GET нет. Дневной/месячный Free-лимит 100/3000 показан как справочный, не автоматически проверенный тариф. |
| Удержание аналитики Resend | Если ответ обрезает начало запрошенного периода, карточка показывает «Частично», не выводит процент месячной квоты. Данные провайдера могут кэшироваться до 15 минут. |
| База и файлы | Размеры фактические; 500 MiB и 1 GiB — прежние ориентиры Free, не автоматическая проверка тарифа. |

Кабинет Resend в момент подключения показывал Transactional Free, 2/100 за день и 2/3000 за месяц, что совпало с агрегатами API. Браузерные JWT, скрытые credential stores и SMTP-пароль для обхода недоступного биллингового API не извлекались.

## Серверная защита и ключи

Использован навык работы с интерфейсом для штатных кабинетов создания ключей. Ограниченные PAT этому аккаунту ещё не доступны; после отдельного разрешения созданы выделенные полные серверные доступы Supabase и Resend. Они хранятся только в Edge secrets:

- `PAW_MONITOR_SUPABASE_TOKEN`
- `PAW_MONITOR_RESEND_KEY`
- `PAW_MONITOR_TOKEN_EXPIRES_AT` — не секрет, дата для предупреждения.

Действующий Resend-ключ SMTP **PawsPatch Supabase Auth** не менялся. При работе с one-time UI первый новый мониторинговый ключ Resend попал в технический вывод. Он **отозван**; замена создана, сохранена и проверена полностью на сервере без вывода её значения. В итоговом кабинете подтверждены только исходный SMTP-ключ и замена **PawsPatch Monitoring Server**. Временный bootstrap отсутствует в развёрнутой функции; файлы bootstrap/test оставлены только как локальная история процедуры, не входят в EXE и не должны включаться в будущий deploy.

`admin-monitor` принимает только POST с отдельным случайным доказательством планировщика, сгенерированным в приватной таблице базы. Проверка через service-role RPC выполняется **до** запросов провайдерам. `verify_jwt=false` не означает анонимного запуска: GET → 405, POST без доказательства → 403, пустые тела. Клиент не может выбрать URL, проект, метод или параметры мониторинга. Все внешние операции рабочего reader — GET, редиректы запрещены, ответы ограничены 1 MiB, отдельный запрос 12 сек, общий бюджет 50 сек, Resend-запросы разнесены по времени. Повторных штормов нет.

RPC запуска/сохранения недоступны `anon` и `authenticated`; чтение приватной таблицы тоже запрещено. Один запуск в минуту, результат привязан к UUID запуска, допустим пять минут и не может быть записан повторно. Админ-RPC возвращают только нормализованный снимок; доказательство планировщика, ключи, run ID, тела ошибок провайдеров не возвращаются. Профили, друзья, сообщения и предложения не изменялись сборщиком.

Применено штатными миграциями:

- `20260908152837_admin_monitor_state` ← local `20260909001500`.
- `20260908154233_admin_monitor_metrics` ← local `20260909001600`.
- `20260908154321_admin_monitor_scheduler` ← local `20260909001700`.

Edge `admin-monitor`, версия **6**, active. Прежний `paw-account-retention` раз в пять минут сохранён; новый `paw-admin-monitor` раз в 15 минут. Мониторинг добавляет около 96 собственных Edge-вызовов в сутки и небольшие агрегатные запросы, но не расходует квоту отправки писем.

## Живая проверка

- Ручной защищённый запуск #35: HTTP 200, не timeout; снимок 2026-09-08 15:42:40 UTC.
- Resend: 2 отправлено, 2 доставлено, 0 ошибок, 0 возвратов за день и месяц; домен подтверждён.
- Auth/DB/REST/Storage: healthy; бакет private, 20 MiB; 5/5 функций ACTIVE.
- Сумма аналитики в первом снимке: 145 запросов, 6 ошибок 4xx и 4 ошибки 5xx за 24 часа. Исторические ошибки показываются предупреждением, не выдаются за текущую недоступность всех функций; отдельная диагностика этих прошлых запросов не выполнялась.
- **Проверен настоящий автоматический запуск** 15:45:00 UTC: cron succeeded; новый снимок 15:45:09, счётчик вызовов 147. Это не только проверка существования расписания.
- До/после: 2 профиля, 67 сообщений, 13 предложений. Для тестов пользовательское содержимое не читалось и не отправлялось.
- Проверены live GRANT: anon/user не могут вызвать monitor begin/store/scheduler; service_role может begin/store, но не приватный cron-helper.
- Советник не добавил предупреждений о публичном доступе к новым RPC. RLS без политик на private-таблицах намеренно запрещает прямой доступ. Прежние замечания SECURITY DEFINER и отключённая проверка утёкших паролей остаются, как описано в исходном release-readiness; массовых изменений прав не делалось.
