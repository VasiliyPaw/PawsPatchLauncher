# Предложение: управление Paw’s Patch

> Историческое предложение. Решения уточнены пользователем и реализованы 08.09.2026: два уровня «Администратор», защищённый `paw`, временные/постоянные блокировки и восстановление 7 дней. Текущее поведение и проверки: [validation-launcher-0.5.9-admin-console.md](validation-launcher-0.5.9-admin-console.md). Остальной текст ниже сохранён как история обсуждения, а не инструкция текущей системы.

Это проект следующего этапа, не включённая админка. Администраторы не назначены, доступ к чужим данным не расширен.

## Название и расположение

Слева внизу — «Управление» со щитом, только для учётных записей с серверной ролью. Внутри три вкладки: «Сервисы», «Пользователи», «Блокировки». Обычное меню и логотип не менять.

Для публичной отметки рекомендую «Команда Paw’s Patch», компактная плашка «Команда» со щитом. Подсказка: «Официальный администратор Paw’s Patch. Роль подтверждена сервером. Никогда не запрашивает пароль или код из письма». Альтернатива — прямое название «Администратор» / «Админ». «Поддержка» лучше оставить отдельной ограниченной роли, если она понадобится: название не должно скрывать полномочия удаления и бана.

## Сервисы

Компактные карточки: вход/аккаунты, база и чаты, хранилище сейвов, отправка писем, источники обновлений. Статусы: «Работает», «Есть ошибки», «Нет данных». Обязательно время последней проверки и последнего успешного события. Нельзя показывать зелёный статус по одному лишь наличию настроек.

Для писем отдельно: доступность отправки, последнее принятие письма провайдером, последняя подтверждённая доставка/ошибка. Принятие письма провайдером не означает доставку в почтовый ящик. Для проверки доставки нужны события Resend или явно запущенное тестовое письмо; не отправлять письма при каждом открытии вкладки. Автопроверка только пока вкладка открыта, с кэшем и ручным обновлением. Никаких ключей SMTP, токенов и кодов восстановления в интерфейсе/логах.

## Пользователи

Список по дате регистрации: старые сверху, новые снизу, как запрошено; переключатель порядка на случай большой базы. Догрузка страниц, а не загрузка всех аккаунтов сразу. Поиск по имени и @username; поиск почты — только в защищённом разделе с минимально необходимыми данными. Серверный поиск с небольшой задержкой после ввода, отменой устаревших ответов и ограничением числа результатов.

В строке: аватарка, имя, @username и подтверждённая роль, присутствие, регистрация с секундами. По нажатию — профиль; действия «Добавить в друзья», «Написать», «Заблокировать аккаунт/почту», «Удалить аккаунт».

Администратор может первым открыть служебный диалог без дружбы. Получатель видит его в чатах и может отвечать. Исключение действует только для этого диалога, а не разрешает всем писать кому угодно. Старые письма/чаты других людей не становятся доступны администратору. После снятия роли бывший администратор теряет возможность создавать такие диалоги; нужно отдельно определить судьбу уже открытых обращений.

Заблокировать подтверждённую команду нельзя, в том числе напрямую через серверный вызов. При этом предлагаю оставить «Отключить звук»: обязательная доступность официального чата не должна означать бесконечные звуковые уведомления. Правило применяется к действующей серверной роли, а не к имени, аватарке или локальному флажку. Плашка выводится рядом с username в списках, профилях, шапке чата, сообщениях и предложениях.

## Блокировки

Отдельный список заблокированных адресов с поиском, причиной, датой и автором действия. Кнопка «Разблокировать» с подтверждением. Блокировка аккаунта и запрет повторной регистрации на его почту — связанные, но разные меры: запись бана должна переживать удаление профиля.

Проверять бан на сервере при создании аккаунта, смене почты и использовании действующей сессии. Завершать/отклонять доступ уже заблокированного пользователя. Одна проверка в интерфейсе регистрации недостаточна. Supabase Before User Created Hook подходит для запрета создания аккаунта, но не заменяет проверки существующих аккаунтов и смены почты.

Нормализация адресов должна быть определена явно; нельзя без разбора удалять точки и +суффиксы у всех провайдеров. Бан одной почты не запрещает человеку зарегистрировать другую почту — не обещать такую защиту.

## Опасные действия и роли

Роли хранить в закрытой серверной таблице, которую пользователь не может редактировать. Проверять текущую роль и активную сессию в каждом привилегированном действии; скрытая вкладка сама по себе не защита. Не встраивать service_role/Resend-ключи в лаунчер. Для удаления/бана — повторное подтверждение личности (желательно MFA), причина, явное подтверждение выбранного аккаунта и защищённый журнал действий.

Назначать/снимать администраторов может только владелец проекта. Нельзя удалить последнего владельца или позволить администратору повысить собственные права. Выдачу первой роли выполнить по явно подтверждённому неизменяемому ID аккаунта, не по одному совпавшему отображаемому имени.

Удаление рекомендую сделать восстановимым на первом этапе: отключить аккаунт и назначить срок окончательного удаления. Если нужно немедленное безвозвратное удаление, до реализации согласовать перечень: Auth, профиль, аватарка, сейвы, дружбы и переписки, а также сохранение журнала модерации. Никаких реальных удалений для проверки функции.

## Что согласовать перед реализацией

1. «Команда Paw’s Patch» или «Администратор»; какой конкретно аккаунт получает роль владельца.
2. Восстановимое или безвозвратное удаление и точный охват данных.
3. Можно ли отключать звук служебного чата; кто получает полномочия бана/удаления помимо владельца.

## Проверка доступа

Отдельно проверить владельца, администратора и обычного пользователя: прямые запросы без роли, просроченная/снятая роль, чужие переписки и файлы, поддельные имя/плашка, ответы только в разрешённом служебном диалоге, запрещённая блокировка команды, бан с активной сессией, смена почты и повторная регистрация, защита последнего владельца. Для разрушительных сценариев — изолированная тестовая база.

Официальные основы: [Supabase RBAC](https://supabase.com/docs/guides/api/custom-claims-and-role-based-access-control-rbac), [Before User Created Hook](https://supabase.com/docs/guides/auth/auth-hooks/before-user-created-hook).
